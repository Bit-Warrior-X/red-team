6/8:
RedScanner v0.3 — CORS scanner (WSTG-CLIENT-07)
Implemented modules/cors_scanner.py. Tests four CORS misconfiguration patterns per URL via curl -I with Origin header injection: (1) unconditional wildcard ACAO:* (medium, CVSS 5.3), (2) arbitrary origin reflection (high, CVSS 7.5), (3) credentialed CORS — ACAO reflects + ACAC:true (critical, CVSS 9.1), (4) domain-suffix spoofing with Origin: https://evil-sec-test.skycloud.tw (high, CVSS 7.5).

Results:
- CORSScanner.run(targets) tests up to 50 URLs from scan surface.
- All four test functions produce typed Vulnerability objects with cvss_score populated.
- No extra tool dependency beyond curl.

Analysis:
- Credentialed CORS (test 3) is the highest-impact pattern; origin reflection alone (test 2) is still exploitable for data theft on non-credentialed APIs.

6/9:
RedScanner v0.3 — TLS scanner (WSTG-CRYP-01)
Implemented modules/tls_scanner.py. Primary path: testssl.sh --jsonfile + _parse_testssl_json() extracting expired certs (high, 8.2), TLS 1.0/1.1 (medium, 5.9), SSLv3/RC4/NULL ciphers (critical, 9.1), weak DH (medium, 5.9). Fallback (openssl): probes -tls1, -tls1_1, -tls1_3 via openssl s_client; cert validity via stdin echo. Port extracted from URL or defaults to 443.

Results:
- TLSScanner with testssl.sh path and openssl fallback; both paths produce standard Vulnerability objects.
- Context: May CDN test (cdn-test-20260604) flagged TLS 1.0 WARN on CDNRay node; this module automates ongoing detection.

Analysis:
- testssl.sh JSON output gives more cipher-level detail; openssl fallback ensures the module runs on any system with openssl installed.

6/15:
RedScanner v0.3 — Directory brute-force scanner (WSTG-CONF-05)
Implemented modules/dirbust_scanner.py with three-tier fallback. Tier 1: gobuster dir with wordlist and extension list. Tier 2: ffuf with FUZZ placeholder. Tier 3: built-in async probe of ~50 critical paths via httpx.AsyncClient (runs without external tools). Severity classification: .env / .git/config / web.config / db dumps → critical (9.1); admin/actuator panels → high (7.5); backup dirs / config files → medium (5.5); other interesting 200/301 → info.

Results:
- DirbustScanner.run(targets) chains gobuster → ffuf → _builtin_probe(); first available tool wins per target.
- Built-in path list covers OWASP top exposed files without needing a wordlist file.
- All findings include cvss_score and remediation guidance.

Analysis:
- Built-in probe covers most impactful paths quickly; gobuster/ffuf needed for deeper wordlist coverage on hardened targets.

6/16:
RedScanner v0.3 — CDN bypass scanner (WSTG-CONF-02 + red team CDN section)
Implemented modules/cdn_bypass_scanner.py. Five tests targeting sec-test.skycloud.tw / CDNRay node: (1) direct origin IP (38.60.218.193) access with Host: header — checks for CDN marker headers; (2) 10 IP-spoofing header variants (X-Forwarded-For, X-Real-IP, CF-Connecting-IP, etc.) — detects status-code diff vs baseline; (3) Host header injection with evil-canary-host.example.com — checks reflection; (4) Set-Cookie without Cache-Control: no-store → cache deception risk; (5) X-Cache-Status presence check.

Results:
- CDNBypassScanner.run(targets) runs all 5 tests against the primary URL.
- cdn_origin_ip read from config (red_plan.json); test 1 skipped if empty.
- All tests via curl -s -I; no extra tool dependency.

Analysis:
- Direct origin exposure (test 1) would allow attackers to bypass CDNRay WAF and DDoS protection entirely. X-Cache-Status check (test 5) cross-validates the CDNRay header finding flagged in May.
